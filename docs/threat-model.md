# STRIDE Threat Model & Automated Security Controls Matrix

This document maps the 10 active attack scenarios in the **Break-the-Flow Attack Lab** and the **Express Resource Server + Local Dev IdP / STS** to the **STRIDE** threat taxonomy, normative IETF RFC sections, runtime middleware controls, and automated Vitest test cases.

---

## STRIDE Threat-to-Control Traceability Matrix

| STRIDE Category | Threat Scenario | Normative Standard | Runtime Control & Middleware | Attack Lab Fault ID | Automated Vitest Verification |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Spoofing** | Unsigned JWT (`alg: "none"`) or `HS256` RSA Public-Key Confusion | `RFC 8725 §3.1` | `createAuthMiddleware` structural header check + `algorithms: ["RS256"]` pinning | `jwt_alg_downgrade` (`none` / `HS256`) | `security.test.ts` — *rejects alg:none unsigned JWTs* & *rejects HS256 key-confusion tokens* |
| **Spoofing** | Cross-Tenant Issuer (`iss`) Substitution | `RFC 7519 §4.1.1` | `decoded.iss !== options.issuer` → `401 invalid_issuer` | `aud_iss_spoof` (`iss`) | `security.test.ts` — *rejects valid RS256 signatures with spoofed audience or issuer separately* |
| **Spoofing** | Authorization Code Interception on Public SPA | `RFC 7636 §4.6` | Web Crypto 384-bit `code_verifier` + Dev IdP SHA-256 `code_challenge` check | `pkce_verifier_mismatch` | `devIdp.test.ts` — *verifies real S256 PKCE authorization_code exchanges and rejects tampered verifiers* |
| **Spoofing** | Login-CSRF / Session Fixation on OAuth Callback | `RFC 6749 §10.12` | One-time `sessionStorage` cryptographic `state` nonce binding | `csrf_state_mismatch` | `flowAndState.test.ts` — *builds 5-stage and 6-stage flow descriptors across nominal, blocked, and recovered states* |
| **Tampering** | Forged JWS Signature or Revoked/Unknown `kid` | `RFC 7517 §4.5` · `RFC 7519` | `jwks-rsa` LRU cache + `SigningKeyNotFoundError` fail-closed `401 unknown_signing_key` / `invalid_signature` | `jwks_kid_miss` (`reject_unknown_kid` / `recover_rotated_key`) | `security.test.ts` — *rejects unknown JWKS kid with 401 fail-closed* & *rejects RS256 tokens with invalid cryptographic signature* |
| **Repudiation** | Unaudited Autonomous AI Agent Tool Invocations | `RFC 8693 §4.1` · `MCP Spec` | Dual-identity `sub` (human) + `act.sub` (agent) logged in `mcpAuditLog` ring buffer (`GET /api/mcp/audit`) | All Stage 06 MCP calls | `mcpSpec.test.ts` — *handles JSON-RPC 2.0 tools/list and tools/call and records audit timeline* |
| **Information Disclosure** | Stolen Agent Bearer Token Replay by Attacker | `RFC 9449 §4.3 & §6.1` | Web Crypto `ES256` DPoP keypair + `cnf.jkt` binding + `dpopReplayCache` (`jti` LRU) | `dpop_token_replay` | `advancedAgentSecurity.test.ts` — *enforces RFC 9449 DPoP sender-constrained agent tokens and rejects stolen token replay* |
| **Information Disclosure** | Autonomous Bulk PII Exfiltration (`export_all_users`) | `RFC 8693` + `CIBA Step-Up` | `cibaApprovalStore` one-time `auth_req_id` push consent bound to `sub` + `tool` (`120s` TTL) | Stage 06 `export_all_users` | `advancedAgentSecurity.test.ts` — *completes CIBA-style human step-up approval and enforces one-time approval consumption* |
| **Denial of Service** | JWKS Cache-Miss Flooding via Random `kid` Headers | `RFC 7517` | `jwks-rsa` `rateLimit: true` (`10 req/min`) + `JwksRateLimitError` → `401 jwks_rate_limited` + `/api/*` rate limiter | `jwks_kid_miss` | `security.test.ts` — *classifies jwks-rsa JwksRateLimitError as jwks_rate_limited* |
| **Elevation of Privilege** | Confused-Deputy Token Passthrough Across Resources | `RFC 8707 §2` · `RFC 9728` | Dedicated `MCP_AUDIENCE` on `/api/mcp` + STS `resource` indicator check (`400 invalid_target`) | `rfc8707_token_passthrough` | `security.test.ts` — *prevents token passthrough between Human API audience and MCP Gateway audience* |
| **Elevation of Privilege** | AI Agent Scope Escalation (`issue_refund`) | `RFC 8693 §2.1 & §5` | STS strips privileged scopes during OBO exchange; `MCP_TOOL_REGISTRY` enforces `refunds:execute` | Stage 06 `issue_refund` | `devIdp.test.ts` — *mints RFC 8693 down-scoped OBO tokens at the STS and blocks scope escalation* |
| **Elevation of Privilege** | Deep Multi-Agent Chaining (`depth > 2`), `act` Cycles, or Unauthorized Actor (`may_act`) | `RFC 8693 §4.1 & §4.4` | `evaluateActChain` (`MAX_DELEGATION_DEPTH = 2`, acyclic) + STS `evaluateMayAct` (`400 unauthorized_client`) | `act_chain_violation` & `unauthorized_actor_may_act` | `delegationPolicy.test.ts` & `security.test.ts` — *enforces RFC 8693 AI Agent Delegation, 60s TTL boundary, nested act chains* |
